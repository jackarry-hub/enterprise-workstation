# QuantXY 量子星河企业工作站

面向决策人、部门负责人、员工、财务和人事的一体化企业协同工作站。系统以“目标输入 → AI 拆解 → 部门与个人执行 → 成果验收 → 风险升级 → 总验收归档”为主线，覆盖项目、任务、业务审批、费用、薪资、客户、知识、Agent、分析与组织管理。

## 商用边界

- 正式工作区只使用服务端会话、Supabase PostgreSQL、RLS 与对象存储；浏览器缓存不承载正式业务记录。
- 业务写入必须经过权限、输入校验、并发版本、审计与失败状态处理。
- 公开导航只显示已通过模块级商业就绪门禁的能力；未完成模块默认拒绝访问。
- 工时类人事功能不在本轮范围，历史数据库字段和迁移仅为数据兼容保留。
- 旧版融合页面与适配器仅作为隔离迁移资产保留，不属于正式 Next.js 工作区依赖图。
- 当前代码尚未部署；数据库、RLS、真实浏览器和容器验收必须在独立 Staging 环境完成后才能判定可上线。

完整操作说明见 [企业工作站使用说明](docs/企业工作站使用说明.md)。

## 本地开发

```powershell
npm ci
npm run dev -- -p 3007
```

打开 `http://localhost:3007`。本地未配置 Supabase 时，正式工作区应显示不可用或空状态，不会降级成示例业务数据。

## 质量门禁

```powershell
npm run typecheck
npm run lint
npm test -- --run
npm run build
```

数据库、RLS、Playwright 全流程和容器检查由商业发布验证器统一编排；没有授权的 Staging 证据时，发布结论保持 `BLOCKED`。

## 数据与密钥

- 数据库与权限：Supabase PostgreSQL + RLS
- 身份：企业身份提供方与 Supabase Auth
- 文件：Supabase Storage
- 审计：不可由普通业务身份修改的服务端审计记录
- 密钥：仅通过运行环境注入，不写入仓库、浏览器存储或测试证据

正式数据不会写入 `localStorage` 或 IndexedDB。清理浏览器缓存不应删除服务端业务数据。

## 容器部署（最终授权后）

本机当前不执行 Docker。最终上线时在 Staging/服务器填写未入库的 `.env.production.local`，再完成镜像构建、非 root/只读文件系统检查、就绪探针、数据库迁移、回滚演练与真实浏览器验收。通过后才允许切换生产流量。

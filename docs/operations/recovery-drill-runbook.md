# QuantXY 恢复与回滚演练手册

演练只能恢复到新建的隔离临时环境，绝不覆盖 Staging 原库或 Production。没有备份 ID、恢复目标指纹、操作者授权和清理负责人时结论为 `BLOCKED`。

## 1. 演练输入

- 候选提交、迁移和镜像摘要。
- 来源备份 ID、恢复点、创建时间和校验状态。
- 全新临时数据库/Storage 目标指纹，名称必须带演练 ID。
- 目标 RPO/RTO、开始时间、操作者和独立复核者。
- 应用回滚版本及其数据库兼容边界。

## 2. 恢复步骤

1. 只读确认备份存在、加密和保留状态，确认临时目标为空且不在任何生产流量中。
2. 由获授权的 Staging Owner 在供应商控制面把备份恢复到临时目标。
3. 验证迁移清单、表/索引/触发器、RLS/FORCE RLS、审计不可变、租户行数和 Storage 对象清单。
4. 使用演练专用密钥启动候选应用，检查就绪由 503 转为 200。
5. 运行七角色、跨租户、核心业务、外部服务替身禁用和文件逐字节校验；不得向真实客户或生产群发送消息。
6. 记录实际恢复点、丢失窗口、恢复耗时，计算实测 RPO/RTO。

## 3. 应用回滚边界

只有数据库迁移明确向后兼容时才允许应用镜像回滚。若候选迁移改变不可逆数据语义，停止应用回滚，改用已验证备份恢复。禁止直接删表、回写伪造版本或手工跳过迁移记录。

在审批门内，服务器操作者可执行：

```text
docker compose up -d --no-build workstation
```

执行前必须把镜像标签解析为审批记录中的摘要；健康检查未通过时不得接流量。

## 4. 失败与清理

任一哈希不一致、跨租户可见、审计可变、对象缺失、RPO/RTO 超标或就绪失败都判定演练失败。保留失败证据，撤销临时凭据，并在复核者确认目标绝非生产后清理临时应用、数据库和 Storage。清理动作需单独审批并记录资源 ID，不使用宽泛通配符。

演练报告必须包含 backup ID、恢复目标、候选/迁移/镜像摘要、开始/结束时间、RPO/RTO、数据与对象校验数、失败项、回滚结果、清理结果和双人签署。

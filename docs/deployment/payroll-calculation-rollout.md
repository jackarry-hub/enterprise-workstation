# 薪资自动核算安全上线指南

本指南用于上线企业工作站的版本化社保、公积金和累计预扣个税核算能力。它不授权生产部署；每次迁移、构建和发布仍需单独批准。

## 上线顺序

1. 先备份生产数据库，并在部署应用镜像前应用 `supabase/migrations/202608210004_payroll_calculation.sql`。
2. 部署应用后不要立即启用自动核算。由拥有 `salary.manage` 权限的薪资负责人进入“系统设置 → 薪资核算参数”，录入企业适用的缴费基数上下限、个人费率和生效月份。
3. 使用页面提供的示例计算复核政策值；只有确认示例结果后才激活该政策版本。
4. 选择一名指定员工和一个非生产工资月份进行试算，不发放、不作为真实工资入账。
5. 由企业薪资专业人员逐项核对：政策输入、应发工资、养老保险、医疗保险、失业保险、住房公积金、累计应纳税所得额、本期个人所得税、扣款合计和实发工资。
6. 使用该员工本人飞书账号登录，确认只能看到本人工资单，不能看到其他员工的金额或身份参数。
7. 试算、权限隔离和专业复核全部通过后，才激活第一个真实工资月份并按企业内部复核流程确认工资单。

## 历史与更正边界

- `calculation_version` 为空的既有工资单按“历史手工记录”继续展示，不会自动套用新政策或重新计算。
- 已确认或已发放的计算工资单不可覆盖。需要更正时应走独立冲正/补差流程，不能修改原始计算快照。
- 其他扣款大于零时必须填写原因；原因与计算结果一并留存，供本人查看和审计。
- 累计预扣依赖同一纳税年度内连续、已确认的历史月份。缺月或缺少期初累计值时系统会阻止计算，不应使用伪造的零值绕过。

## 环境与安全

- 薪资核算不引入新密钥，使用现有服务端 `SUPABASE_SERVICE_ROLE_KEY` 访问受控数据。
- 不得创建任何 `NEXT_PUBLIC_*` 薪资密钥，也不得把工资、税额、社保基数或员工信息写入 `.env`。
- 浏览器只接收当前登录员工的工资单；工资保存、政策维护和计算预览都在服务端重新鉴权和计算。
- 不得把生产工资输入、试算响应或真实员工税务数据提交到 Git、测试快照、日志或工单附件。

## 发布前检查

```bash
npm run test:unit
npm run test:html
npm run typecheck
npm run lint
npm run build
```

本地 Supabase 可用时再执行：

```bash
npm run db:reset
npm run db:test
```

如果本地 Supabase 不可用，必须明确记录数据库验证未执行，不能将静态 SQL 合同测试描述为真实数据库迁移通过。

发布完成后保留以下证据：应用 Commit、迁移文件名、激活政策版本与生效月份、指定员工试算复核人，以及本人数据隔离验证结果。证据中不得包含真实工资金额或密钥。

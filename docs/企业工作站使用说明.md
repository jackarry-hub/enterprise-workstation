# QuantXY 企业工作站使用说明

版本：商业候选版
适用角色：决策人、部门负责人、员工、财务、人事

## 1. 使用边界

QuantXY 把目标、项目、任务、审批、费用、薪资、客户、知识、Agent 与分析连接为可审计的业务闭环。工时类人事功能暂不在本轮范围。正式工作区只读取服务端真实数据；未配置数据库或权限时显示明确的空状态或错误，不使用示例记录替代。

当前代码尚未部署。内部试用前必须在独立 Staging 环境完成数据库迁移、RLS、对象存储、真实身份、桌面端和移动端验收。

## 2. 登录与权限

1. 通过企业统一登录入口进入系统。
2. 服务端根据组织、部门、职级、角色和权限码生成当前会话。
3. 左侧导航和移动端底栏只显示当前身份可用且已通过商业就绪门禁的模块。
4. 直接访问越权地址会被服务端拒绝，并返回岗位首页。
5. 退出后服务端会话失效，浏览器缓存同时清理。

管理员应先在“系统设置”检查组织资料、身份提供方、通知策略、AI 运行策略和可用能力；保存成功后刷新页面复核持久化结果。

## 3. 决策与项目闭环

1. 决策人进入“AI 决策调度台”，输入目标、期限、预算和约束。
2. AI 生成部门目标、唯一负责人、个人任务、依赖关系和验收标准。
3. 人工确认后下发，系统创建真实项目、任务和责任关系。
4. 负责人协调依赖、资源和风险；执行人更新进度并上传成果。
5. 指定验收人通过或退回，系统保留版本和操作轨迹。
6. 全部任务与协同事项关闭后，决策人完成总验收和归档。

任务写入采用版本并发控制。发生冲突时应刷新后重新操作，不能覆盖他人已提交的更新。

## 4. 任务与成果

1. 在“我的执行台”或“任务管理”查看负责人、期限、前置依赖和验收标准。
2. 前置任务完成后开始执行；阻塞时填写原因并上报。
3. 上传真实成果文件，确认文件可访问后提交验收。
4. 验收人填写意见并通过或退回。
5. 逾期、阻塞和验收超时进入通知与管理行动清单。

系统不允许无成果进入验收，也不允许执行人直接把自己的任务改为完成。

## 5. 业务审批与费用

审批中心只展示当前账号按 RLS 可见的报销、采购和合同流程。

1. 有权限的员工发起费用报销，填写项目、金额、币种、日期和说明。
2. 服务端保存草稿或提交审批，并生成流程步骤和审计记录。
3. 当前审批人通过、拒绝或退回；非当前审批人不能操作。
4. 财务按权限更新付款状态和付款参考号。
5. 列表、详情、通知和分析读取同一份服务端记录。

## 6. 薪资

- 普通员工只能查看本人工资单。
- 财务、人事或授权管理员按权限查看和管理可见员工范围。
- 基础工资由部门、职级与有效薪资政策计算；未配置政策时必须显示“待配置”，不得回填推测金额。
- 奖金、扣减、净薪资、工资单状态与发放时间均来自数据库记录。
- 工资周期侧栏根据当前真实工资单计算进度，不显示写死日期或人数。

## 7. 组织、人事与客户

组织人事模块维护部门、职级、员工档案、汇报关系和薪资档位政策。客户模块支持新建客户、记录跟进、推进阶段和查看负责人；所有写入都要经过权限、租户隔离、输入校验和审计。

## 8. AI、Agent、排期与知识库

- AI 助手：创建真实会话，服务端保存消息、用量、错误与追踪信息。
- Agent 中心：按部门和职级判定可调用范围，支持 Agent 创建、权限申请、编排和运行记录。
- 智能排期：根据真实任务、资源和依赖生成方案，人工确认后才写入业务计划。
- 知识库：上传文件后进入处理队列，保留版本、解析状态、失败原因和可重试记录。

所有外部调用必须配置超时、重试上限、幂等键、审计和安全的目标地址校验。

## 9. 通知与数据分析

通知中心聚合任务、业务审批、费用、客户、知识和 Agent 事件。每条通知都有真实接收人、目标页面和已读状态；移动端点击后进入对应处理页。

数据分析通过服务端聚合接口返回指标定义、分子、分母、时间范围和数据时间点。页面不使用写死趋势或演示图表；无数据时显示空状态。

## 10. 桌面端与移动端

- 桌面端使用岗位导航、全局搜索、通知中心和页面级快速创建。
- 移动端使用底部主导航、页面级创建按钮和底部操作面板，触控目标不小于 44px。
- 快速创建只展示与当前页面相关且当前账号有权执行的动作。
- 离线时可浏览已缓存的静态外壳，但业务写入会被阻止并提示恢复网络后重试。
- 退出登录会清理 PWA 静态缓存，不缓存 API、业务响应或文件内容。

## 11. 数据与文件

- 正式业务数据：Supabase PostgreSQL + RLS
- 身份：企业身份提供方与 Supabase Auth
- 文件：Supabase Storage
- 审计：普通业务身份不可修改的服务端记录
- 浏览器：只保存必要的界面偏好和静态资源，不作为正式业务数据库

管理员应配置数据库与对象存储备份、恢复演练、日志保留、密钥轮换、HTTPS 和企业域名。

## 12. 常见问题

### 页面显示暂无数据或服务不可用

检查 Staging/生产环境变量、数据库迁移、RLS、当前账号组织成员关系和服务就绪状态。不要通过开启示例数据绕过问题。

### 为什么任务不能开始

检查前置依赖、当前状态、负责人权限和记录版本。所有依赖完成后才能开始。

### 为什么不能提交验收

任务必须处于执行中，且至少存在一个成功上传并可读取的成果文件。

### 为什么无法保存

先查看页面错误码。权限不足、版本冲突、输入错误和服务故障会分别给出可追踪的失败状态。

### 为什么页面自动返回岗位首页

当前账号没有目标模块权限，或该模块尚未通过商业就绪门禁。

## 13. 内部试用验收

1. 使用五类岗位真实测试账号登录，验证导航与直接地址权限。
2. 完成目标拆解、项目下发、任务执行、文件上传、验收和归档。
3. 完成报销创建、审批、退回、再次提交和付款状态更新。
4. 验证组织、职级、薪资政策和本人工资单隔离。
5. 完成客户新增与跟进、知识上传与处理、Agent 创建与运行、AI 会话和排期确认。
6. 在通知中心打开对应业务记录并验证已读状态。
7. 在桌面 Chrome、iPhone、Android 和平板尺寸完成关键链路。
8. 验证断网提示、重复提交、并发冲突、越权、超时、失败重试和审计记录。
9. 完成容器就绪、备份恢复、回滚和候选版本证据签名。

只有所有强制门禁通过且无高风险阻塞项，才能批准上线。

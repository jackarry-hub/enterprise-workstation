# 企业工作站使用说明

版本：最终本地交付版  
适用角色：决策人、部门负责人、员工、财务、人事

## 1. 系统解决什么问题

企业工作站把领导命令、部门责任、个人任务、跨部门支持、审批、成果和复盘连接在同一条业务链上。领导不需要理解项目管理术语，只需说明目标、截止时间、预算和约束；AI 会生成部门目标、唯一负责人、个人任务、依赖关系和验收标准。

完整闭环：

1. 决策人输入目标。
2. AI 拆解部门与个人任务。
3. 决策人确认后下发。
4. 员工或负责人执行任务。
5. 执行人上传成果并提交验收。
6. 指定验收人通过或退回。
7. 阻塞、逾期或验收超时自动进入领导行动清单。
8. 全部任务完成后，领导总验收并归档。

## 2. 启动与进入

在项目目录执行：

    npm install
    npm run dev -- -p 3007

浏览器打开 http://localhost:3007 。右上角用户菜单可以切换五类试用身份：

- 李总：决策人
- 张伟：部门负责人
- 陈晨：员工
- 周倩：财务
- 李琪：人事

本地身份切换用于流程验收。正式上线时应接入企业统一身份或 Supabase Auth。

## 3. 决策人操作

### 3.1 下达命令

1. 进入“AI 决策调度台”。
2. 点击“发起新决策”。
3. 填写战略目标、硬性截止、预算上限和关键约束。
4. 点击 AI 拆解。
5. 检查部门目标、负责人、任务、依赖和验收标准。
6. 确认方案并下发。

下发后，任务会同时出现在专项项目、任务中心、负责人推进台和个人执行台。

### 3.2 管理风险和周报

“今日必须处理”按紧急程度显示依赖异常、阻塞超时、任务逾期、验收超时和待领导审批。领导首页的“本周执行摘要”自动统计完成率、推进中、待验收、阻塞、逾期、依赖风险和待审批数量；点击“复制周报”可直接复制文字摘要。

### 3.3 总验收与归档

只有当全部任务完成、协同请求关闭后，才能提交总验收。总验收通过后可完成归档，已验收成果会进入业务闭环知识。

## 4. 部门负责人操作

1. 在“负责人推进台”承接部门目标。
2. 检查 AI 分配人员，协调阻塞和跨部门支持。
3. 员工提交成果后，对照验收标准填写意见。
4. 通过成果或退回修改。
5. 在请假或考勤页面处理团队审批。

负责人本人执行的任务不能自提自批，会自动交给决策人验收。

## 5. 员工操作

### 5.1 执行和交付

1. 在“我的执行台”查看任务、期限、验收标准和前置依赖。
2. 前置任务完成后点击“开始执行”。
3. 更新进度；遇到问题时填写阻塞原因并上报。
4. 需要预算、增员或培训时发起协同请求。
5. 上传成果文件，确认文件可下载后提交验收。

系统不允许没有成果文件的任务进入验收，也不允许执行人直接把任务改为完成。

### 5.2 考勤与个人事项

- “考勤管理”：签到、签退、补卡和加班申请。
- “请假管理”：提交请假并查看负责人、人事处理状态。
- “薪资管理”：只查看本人工资单。

## 6. 财务操作

1. 处理预算、采购等财务协同。
2. 人事完成考勤封账后执行薪资核算。
3. 等待人事复核和领导批准。
4. 财务完成最终发放。

薪资顺序不能跳过：考勤封账 → 财务核算 → 人事复核 → 领导批准 → 财务发放。

## 7. 人事操作

1. 处理增员、培训和人员支持。
2. 维护组织档案与考勤制度。
3. 复核请假、补卡和加班。
4. 完成考勤封账并复核薪资人员数据。

## 8. 项目管理

项目详情包含：

- 概览：目标、健康状态、成员和动态。
- 里程碑：创建和查看关键节点。
- 任务：创建、分配、评论和状态查看。
- 甘特图：根据任务与里程碑日期自动生成。
- 文件：上传真实文件内容，刷新后仍可下载。
- 日报：成员提交今日完成、下一步、阻塞和支持需求。
- 复盘：负责人维护结果、有效做法、经验教训、后续动作并收口风险。

AI 决策创建的专项项目必须从执行工作台推进，项目详情不能绕过验收流程直接改状态。

## 9. 活动、客户和分析

活动使用统一项目仓库。创建活动后会同步出现在活动推进和项目管理中，并自动生成策划、执行、推广、复盘四个阶段。

客户管理支持新建客户、筛选、查看档案、记录跟进并推进客户阶段。客户资料保存在当前浏览器，刷新后继续存在。

数据分析向决策人和部门负责人展示执行趋势、交付日历、风险提醒和真实任务周报；部门负责人只能查看本部门范围。

## 10. 通知与行动清单

顶部铃铛显示当前角色未读通知。通知来自真实任务、审批、协同和执行动态。

- 点击通知进入处理页面并标为已读。
- 通知中心支持逐条已读和全部已读。
- 每个角色只收到自己职责范围的内容。
- 新任务、阻塞、验收、逾期或审批出现时自动提醒。

## 11. 文件与数据保存

本地交付版把业务记录保存在 localStorage，上传文件保存在 IndexedDB。刷新不会清除；清理浏览器站点数据、更换浏览器或更换电脑会导致本地数据不可用。

正式部署建议：

1. 配置 Supabase 数据库、Auth 和 Storage。
2. 建立数据库和对象存储备份。
3. 配置 HTTPS、域名与审计日志保留周期。

## 12. 常见问题

### 为什么任务不能开始？

检查前置依赖。所有前置任务完成后，按钮才会变为“开始执行”。

### 为什么不能提交验收？

任务必须处于执行中，并至少上传一个成果文件。

### 为什么负责人不能验收自己的任务？

系统执行职责分离，负责人自己的交付由决策人验收。

### 为什么不能进行薪资核算？

人事必须先处理所有考勤异常并完成考勤封账。

### 为什么页面自动跳回首页？

当前角色没有该页面权限。请从当前岗位导航进入允许模块。

### 示例文件为什么不能下载？

内置示例记录只有文件元数据；用户自己上传的文件包含真实内容，可以下载。

## 13. 最终验收建议

1. 李总下达命令并确认下发。
2. 陈晨开始任务、上传成果并提交验收。
3. 张伟完成验收或退回。
4. 员工发起协同，财务或人事处理。
5. 员工提交请假、补卡和加班。
6. 负责人和人事逐级审批。
7. 人事考勤封账。
8. 财务核算、人事复核、领导批准、财务发放。
9. 李总查看通知、周报并完成总验收归档。

# 项目详情页（概览与里程碑）设计规格

## 已确认范围

- 新增动态路由 `/projects/[id]`，作为项目负责人推进、成员执行和管理层查看状态的核心页面。
- 严格延续现有企业工作站的白蓝渐变、玻璃拟态、半透明卡片、大圆角与柔和阴影。
- 视觉基准为 `C:\Windows\TEMP\enterprise-workstation-designs\05_企业工作站_项目详情任务看板.png`。
- 本阶段实现详情页框架、概览 Tab、里程碑 Tab；任务、甘特图、文件、日报、复盘仅显示可切换的阶段占位内容。
- 不新增任务中心或其他业务模块。

## 页面结构

### 顶部项目信息

使用横向 GlassCard 展示项目名称、状态、负责人、成员头像组、项目周期、截止时间和当前进度。右侧提供“编辑项目”“添加任务”和“更多”操作。桌面端保持设计稿的横向信息密度；移动端改为单列标题与两列信息网格。

### 项目 Tab

顺序固定为：概览、里程碑、任务、甘特图、文件、日报、复盘。七个 Tab 都可以切换；后五个 Tab 只显示“模块将在后续阶段开放”的明确占位，不创建对应功能或路由。小屏幕使用横向滚动，不换行。

### 概览 Tab

- 项目目标和项目描述。
- 项目健康状态：项目进度、任务完成率、活跃风险数、延期数量。
- 项目成员：负责人和成员头像、姓名与职责。
- 项目动态：最近的项目操作记录。
- 不渲染任务列表、看板或任务操作。

### 里程碑 Tab

- 顶部展示里程碑总数、已完成、进行中与整体完成率。
- 主体按 `sortOrder` 排序，展示阶段名称、负责人、开始时间、截止时间、状态、描述和完成百分比。
- “新增里程碑”打开表单，可填写阶段名称、负责人、开始时间、截止时间和完成百分比。
- Supabase 可用时写入 `milestones`；配置缺失或写入不可用时在当前页面加入本地 Mock 里程碑，保证交互可体验。

## 数据架构

动态路由是 Next.js 15 Server Component，`params` 类型为 `Promise<{ id: string }>` 并在服务端 `await`。服务端通过现有 `@supabase/ssr` 客户端按 `projects.public_id` 查询项目，再用内部 `projects.id` 并行查询 `project_members`、`milestones`、`tasks`、`project_activities` 和 `project_risks`。

数据返回统一为：

```ts
type ProjectDetailResult = {
  detail: ProjectDetailData;
  source: "supabase" | "mock";
};
```

Supabase 配置缺失或查询失败时，只对同一 `public_id` 使用现有 Mock 数据；未知 ID 进入 Next.js `notFound()`。当前 Schema 没有公开员工姓名资料表，因此真实项目成员资料不足时使用同项目 Mock 映射或“项目负责人 / 项目成员”安全回退。

新增里程碑通过 Server Action 校验项目与项目成员，再使用当前会话和 RLS 写入。客户端在写入不可用时只保留本次会话的本地结果，不伪装为已持久化。

## 交互与状态

- 项目列表中的项目名称和操作入口导航到对应详情页。
- “添加任务”切换到任务占位 Tab，不开发任务中心。
- “新增里程碑”表单提交后立即更新当前里程碑列表。
- 缺少里程碑或动态时显示明确空状态；未知项目使用 404。
- 侧边栏在 `/projects/[id]` 下仍保持“项目管理”选中。

# 移动端岗位工作台统一改版设计

## 目标

把负责人、员工、财务、人事四个岗位工作台统一为适合 360–430px 手机宽度的轻量任务界面。首屏优先回答三个问题：我是谁、现在最该做什么、点击哪里开始办理。保留现有完整业务数据和闭环能力，不改变权限、任务状态或流程规则。

参考原则：

- Linear Mobile：移动端围绕需要立即处理的工作组织入口，重要任务优先，点击整行进入办理。
- Linear My Issues：按紧急、SLA、阻塞、进行中等焦点顺序分组，只有适用分组才显示。
- Material 移动端列表：紧凑屏幕使用单列列表；主文本、辅助信息和尾部操作保持固定对齐，方便快速扫描。

## 页面信息架构

### 1. 紧凑身份头部

- 左侧显示岗位名称和一句当前职责，不再使用大号标题、眉题、长说明三层结构。
- 右侧显示头像、姓名和职位，部门作为次级信息。
- 负责人、员工、财务、人事共享同一布局，只替换岗位文案。

### 2. 今日概览

- 把原来的四张统计卡压缩为一条横向概览：待处理、进行中、已完成。
- “需要关注”不再单独占一张大卡；当数量大于零时显示醒目提示点和数量。
- 上游输入和下游结果合并为一条可读流程提示：`接收什么 → 交付什么`。

### 3. 今日行动列表

- 使用单列、整行可点击的任务列表，替代两列大卡。
- 每行最多三层信息：任务标题；优先级、状态和截止时间；一行简短说明。
- 左侧使用 3px 优先级色条，紧急为红色、待处理为橙色、可推进为蓝色。
- 右侧只保留一个箭头或主状态，不重复显示“处理”文字。
- 列表按紧急、阻塞、待验收、审批时限、普通推进排序，最多显示 4 条；空状态只显示一句完成提示。

### 4. 任务办理区

- “我的执行任务”“我负责验收”“岗位协同事项”继续严格按当前身份隔离。
- 列表默认只展示任务摘要；点击任务行后在原页面展开唯一一个办理详情。带任务锚点进入页面时自动展开并定位对应任务。
- 展开详情保留现有开始执行、上传成果、提交验收、退回修改、申请预算、申请人员、工资发放等真实操作。
- 不显示“最近流转”等与当前办理无直接关系的泛化动态。

### 5. 常用入口

- 常用入口移到今日行动列表后、任务办理区前。
- 使用 2 列轻量入口，不再使用整块浅蓝背景包裹多个按钮。
- 每个岗位只显示与其职责相关的入口，重复入口只保留一处。

## 演示身份选择

- 删除原生 `<select>` 展开的系统下拉样式。
- “我的”页面显示一张当前身份卡，点击后打开移动端底部弹层。
- 弹层中每个身份是一条清晰列表：头像、姓名、职位、部门；当前身份显示对勾。
- 点击某个身份后立即切换并关闭弹层，跳转到该身份对应工作台。
- 身份列表可滚动，底部导航保持不被遮挡；支持键盘焦点和明确的可访问名称。

## 视觉规范

- 页面背景保持浅蓝白色，不新增复杂渐变或大图。
- 一级容器圆角 20px，列表行圆角 14px；减少卡片嵌套层数。
- 统一间距：页面左右 16px，区块间 16px，列表行内边距 14px。
- 标题 22px，任务标题 15px，辅助信息 12px；禁止在手机宽度使用两列任务卡。
- 阴影只用于顶层卡片和身份弹层，列表项主要用边框和背景层级区分。

## 数据与交互

- 继续使用现有 `useOperations`、角色权限和本地演示状态，不新增数据源。
- 今日行动项继续由 `getOperationActionItems` 产生，点击地址保持真实任务、审批、工资和考勤办理路径。
- 身份切换继续调用现有 `demo.switchIdentity`，只替换呈现组件。
- 所有显示出来的按钮必须具备真实点击行为；不可操作状态用文字或徽标表达，不伪装成禁用按钮。

## 异常与空状态

- 当前岗位没有任务时显示“当前没有需要处理的事项”，不展示空卡片网格。
- 某任务尚未满足前置条件时，在展开详情内解释需要上传文件或填写意见，不在列表页展示不可点击按钮。
- 身份切换失败时保持当前身份，并在弹层内显示简短错误提示。

## 验证标准

- 360px、390px、430px 宽度无横向滚动、文字裁切或两列任务拥挤。
- 四个岗位工作台首屏可看到身份、核心数字和最多 3 条今日行动；不足 3 条时不使用空卡片补位。
- 每条今日行动整行可点击并到达对应办理位置。
- 每个岗位只显示本人任务和本岗位入口。
- 身份弹层可以切换十个演示身份，当前身份有明确选中状态。
- 回归验证任务 0→100、个人提交、负责人验收、CEO 总验收、薪资五节点和通知回写。

## 不在本次范围

- 不修改业务状态机、角色权限规则和数据字段。
- 不新增桌面端视觉稿。
- 不新增后端、登录方式或第三方依赖。

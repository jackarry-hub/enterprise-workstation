# 企业工作站一期设计规格

## 范围

本规格保持已审核架构不变，仅落实审核补充项，并开发一期：Next.js 项目初始化、Supabase 连接、全局 Layout、Sidebar、Header 与 Dashboard。

一期不实现项目、任务、活动、人事、考勤、薪资、审批的业务增删改流程，但必须预留清晰的功能域目录与导航边界。

## 技术基线

- Next.js 14+，App Router，TypeScript。
- Tailwind CSS，Shadcn UI，Lucide React。
- Supabase Auth、PostgreSQL、Storage。
- 桌面端以 `docs/design-reference/02_企业工作站_首页驾驶舱.png` 的 1672 x 941 画布为视觉基准。
- 移动浏览器必须无横向溢出，侧栏转换为抽屉导航。

## 功能域目录

`src/features` 必须包含：

- `dashboard`
- `projects`
- `tasks`
- `activities`
- `hr`
- `attendance`
- `salary`
- `approvals`

## 权限角色

系统预置六类业务角色：老板、管理员、部门负责人、普通员工、HR、财务。

- 老板：企业全局数据查看与经营驾驶舱权限。
- 管理员：系统配置、成员、角色和权限管理。
- 部门负责人：本部门项目、任务、人员和审批数据。
- 普通员工：本人任务、日程、考勤、薪资与申请数据。
- HR：组织人事、考勤和人事类审批。
- 财务：薪资、报销、采购和财务类统计。

数据库访问同时受组织成员身份和角色权限约束，不能只依赖前端隐藏菜单。

## 数据库补充

- `roles`：组织内角色，包含稳定代码、中文名称、说明、系统内置标记和启用状态。
- `files`：统一文件元数据，记录组织、Storage bucket/path、文件名、MIME、大小、上传人和可选业务对象关联。

所有业务数据携带 `organization_id`，外键列建立索引，并启用 RLS。

## UI 组件

- `GlassCard`：半透明白色表面、浅色描边、背景模糊与柔和阴影。
- `DataCard`：图标、指标名称、主要数字和趋势信息。
- `StatusBadge`：进行中、已完成、预警和中性状态。
- `ProgressBar`：可访问的百分比进度条。
- `PageHeader`：页面标题、副标题和可选操作区。

## Dashboard 组成

- 固定桌面侧栏和顶部 Header。
- 欢迎区与企业运行问候。
- 企业员工、进行项目、今日任务、整体完成率四张数据卡。
- 项目健康度、任务趋势、待办事项。
- 活动推进、通知公告、即将日程。
- 团队协作与项目动态区域。

数据在一期使用类型安全的演示数据；Supabase 连接层与表结构同时完成，二期可替换为服务端查询而不重写 UI。

## 响应式与验收

- 1440px 以上保持设计稿的侧栏、顶栏和多栏密度。
- 768px 至 1439px 折叠部分面板并使用两栏布局。
- 小于 768px 使用抽屉侧栏、单列内容和紧凑 Header。
- 图表、卡片、导航、状态色、圆角、背景和间距应与设计稿保持同一视觉系统。
- 必须通过类型检查、Lint、单元测试、生产构建和桌面/移动端浏览器验证。

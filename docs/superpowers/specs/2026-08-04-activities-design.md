# 活动推进模块设计说明

## 业务流程

活动推进不是独立业务体系，而是项目协同的一种执行视图：

企业目标 → 活动项目 → 策划/执行/推广/复盘里程碑 → 阶段任务 → 进度反馈。

## 用户角色与场景

- 活动负责人：查看活动总体状态、切换活动并推进里程碑与任务。
- 活动成员：查看当前阶段任务、负责人和截止时间，按计划执行。
- 管理层：通过活动列表和详情进度快速判断活动健康度。

## 数据模型

- 活动主体复用 `Project`。
- 活动负责人和成员复用 `ProjectMember` / `MemberSummary`。
- 策划、执行、推广、复盘复用 `Milestone`。
- 阶段工作项复用 `ProjectTask`。
- Demo V1.0 仅增加活动页面聚合类型和 Mock 组合，不新增数据库表或临时字段。

## 页面结构

1. PageHeader 与活动统计。
2. 左侧活动列表：名称、负责人、周期、进度、项目状态。
3. 右侧活动详情：活动目标、负责人、当前进度。
4. 四阶段推进：策划、执行、推广、复盘。
5. 当前活动任务列表：任务、负责人、截止时间、优先级、状态、进度。

## 交互边界

- 点击活动列表项切换右侧详情。
- 不新增活动创建流程、任务中心或复杂审批。
- 页面内操作只服务活动浏览和推进判断。

# AI结构化调度、员工工作画像与飞书通知设计

## 目标

把当前正式工作站的AI调度从“偶发JSON解析失败后静默回退”升级为稳定、可验证的结构化任务生成；把员工匹配从岗位近似匹配升级为基于真实技能、交付证据和当前负荷的可解释推荐；把批量下发升级为按员工合并的飞书任务卡片，员工点击后直接进入自己的任务执行页。

## 边界

- 仅修改AI企业工作站项目及其Supabase数据结构，不接触服务器其他项目。
- API Key、飞书App Secret、Supabase Service Role Key只保留在服务端。
- 工资、奖金和任何薪酬字段不进入任务匹配，也不出现在同事画像中。
- “工作画像”只描述专业能力、任务偏好、成长方向和可用容量，不做心理或人格判断。
- AI只给出候选人与解释，最终分配权属于有`task.manage`权限的负责人。
- 批量下发最多20项任务；同一员工在一次下发中只收到一张汇总卡。

## 1. AI结构化输出

浏览器向现有`/api/ai/chat`传入`structured_output: true`。服务端固定向DeepSeek增加JSON输出模式并关闭思考输出，检查最终`message.content`必须为非空JSON对象，同时拒绝`finish_reason=length`的截断结果。第一次空内容、截断或非法JSON时，服务端使用同一请求重试一次；第二次仍失败则返回稳定错误`upstream_invalid_response`，不向浏览器暴露上游原文。

浏览器将WBS请求上限提高到2400 tokens，并要求每项任务返回技能数组。浏览器仍执行任务数量、字段长度、日期和优先级的业务校验；无法通过时使用内置模板，但提示应明确为“AI输出格式异常，已使用内置方案”，不再误导为API Key失败。

## 2. 员工工作画像

复用现有`employee_skills`、`skill_tags`和技能验证状态，新建`employee_work_profiles`保存员工可自助维护的信息：

- 专业简介，最多240字。
- 偏好任务类型，最多8项。
- 成长方向，最多8项。
- 每周可投入工时，1至80小时。
- 自评技能及1至5级熟练度，最多20项。

同组织成员可以读取用于协作分配的专业画像；员工只能写自己的画像。系统在正式启动数据中合并已验证技能、自评技能和任务交付指标，计算当前进行中任务数、已逾期数、已完成数、按时完成率与近似负荷。

正式HTML新增“我的工作画像”页面。员工能编辑自己的简介、偏好、成长方向、容量和自评技能；移动端入口放在“更多”中，不增加首页信息密度。

## 3. 可解释任务推荐

AI任务同时给出`skills`。对每项任务先过滤无效或不可用人员，再为所有候选人计算：

- 技能匹配40分：已验证技能权重高于自评技能。
- 岗位/部门匹配25分。
- 历史按时交付18分。
- 当前容量与负荷12分。
- 响应与成长偏好5分。
- 逾期和过载作为扣分项。

调度页面显示前三名候选人的总分、匹配技能、当前负荷和风险。负责人可以保留推荐人或改派，系统不自动覆盖人工选择。

## 4. 飞书批量通知

新增正式批量任务接口。接口校验整批输入后创建任务，读取每个任务已有的通知上下文，按员工`open_id`分组并发送交互卡片。卡片展示本次任务数量、每项任务名称/优先级/截止日期，并提供“进入我的任务”按钮。单个员工收到一项任务时仍使用现有单任务卡片。

发送成功后，每个任务的`task_notifications`记录使用同一飞书消息ID标记为已发送；失败任务返回稳定错误码并可在任务详情中重发。浏览器显示“已创建N项，飞书送达X项，未送达Y项”，避免把任务创建成功与通知成功混为一谈。

## 5. 验证与发布

必须通过单元测试、HTML交互测试、TypeScript、ESLint、生产构建和Compose语法验证。数据库迁移先做远程只读检查，再仅向当前Supabase项目推送新增迁移。应用仅更新`ai-brain-demo` Compose项目。上线后创建一项明确标注为测试的任务给“赛博老爸 / 用户555038”，验证只发送一条飞书通知并可以打开对应任务。

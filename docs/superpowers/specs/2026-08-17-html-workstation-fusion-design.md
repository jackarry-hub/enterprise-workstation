# QuantXY 单文件工作站融合设计

日期：2026-08-17

## 1. 目标

以 `quantxy-ai-workbench_10(1).html` 为产品与视觉基线，在不改造线上 Next.js 项目、不覆盖原始 HTML 的前提下，制作一个可独立打开的融合版单文件工作站。

融合版吸收线上企业工作站中适合业务执行的内容，形成“客户目标进入—项目或活动承接—任务执行—业务决策—成果验收—经营复盘”的闭环。考勤、请假、发薪和传统工资单不在本轮范围内。

## 2. 交付物

- 新文件：`E:\新企业工作站\quantxy-ai-workbench-fused.html`
- 原文件保持不变。
- 当前 Next.js 项目源码保持不变。
- 融合版继续使用单文件 HTML、CSS、JavaScript 和浏览器本地存储，可直接打开或通过本地静态服务器运行。

## 3. 保留内容

保留原 HTML 的视觉语言、侧边导航、顶部搜索、身份切换和以下现有能力：

- 决策驾驶舱
- 项目中心
- AI 调度中心
- 任务中心
- 员工工作台
- AI 助理
- 数据洞察
- 知识中心
- Agent 中心
- 财务中心
- 组织与权限
- 系统设置

财务中心继续承担经营收入、成本、预算、现金流和财务洞察，不增加薪资或考勤流程。

## 4. 新增与融合模块

### 4.1 客户与交付

新增侧边导航页面，包含：

- 客户总数、本月新增、跟进中、已成交金额等摘要。
- 客户列表及状态、来源、行业、负责人、最近联系和成交进度筛选。
- 客户详情，展示联系人、需求、跟进记录、关联项目、下次跟进时间和成交阶段。
- 新建客户入口，使用现有单文件表单和本地持久化模式。
- 从客户记录跳转或创建关联项目。

### 4.2 活动推进

新增侧边导航页面，活动作为特殊项目类型存在，包含：

- 活动数量、进行中数量、完成率和 ROI 摘要。
- 活动列表、负责人、周期、目标和整体进度。
- 策划、执行、推广、复盘四阶段推进状态。
- 关键节点、阶段任务和关联项目。
- 新建活动入口，活动任务可进入现有任务中心。

### 4.3 业务决策中心

基于原 HTML 已存在的业务审批数据新增独立页面，统一处理：

- 采购申请
- 合同审批
- 预算申请
- 项目变更
- 费用报销
- 成果验收

页面提供“待我决策、我发起的、已完成”分类和通过、驳回操作。请假、考勤和薪资审批不进入该模块。

### 4.4 决策驾驶舱融合

首页保留原有经营指标与 AI 战略输入，不增加大面积重复模块。新增三个紧凑入口：

- 重点客户机会
- 重点活动进度
- 待我决策

这些入口展示最高优先级记录并跳转至对应页面。

4. 活动推进
5. AI 调度中心
6. 任务中心

8. 员工工作台
9. AI 助理

侧边栏保持可滚动，现有交互和视觉样式不变。

## 6. 数据结构与关联

新增本地状态集合：

- `customers`：客户基础信息、阶段、负责人、成交进度、跟进时间和关联项目。
- `activities`：活动目标、负责人、周期、阶段、进度、ROI、关联项目和任务。
- `decisions`：业务类型、标题、申请人、金额或影响、状态、时间和关联对象。

关联规则：

- 客户可以关联一个或多个项目。
- 活动可以关联项目和现有任务。
- 决策可以关联客户、项目、活动、任务或交付成果。
- 首页摘要从上述真实本地状态计算，不维护重复统计值。
- 新增集合与现有任务、项目、成员、知识和 Agent 状态一起保存到浏览器本地存储。

## 7. 主要交互流程

### 客户交付流程

新建客户 → 记录需求与跟进 → 转为项目 → 创建任务或活动 → 提交成果 → 业务验收 → 数据洞察。

### 活动推进流程

新建活动 → 设置目标、负责人和周期 → 拆分阶段任务 → 进入任务中心执行 → 更新阶段进度 → 复盘归档。

### 业务决策流程

业务记录发起决策 → 决策中心集中处理 → 通过或驳回 → 更新关联对象状态 → 写入动态记录。

## 8. 错误与空状态

- 没有客户、活动或决策时显示明确空状态和创建入口。
- 表单必填项缺失时不保存，并显示现有 Toast 风格提示。
- 关联项目或成员已被删除时显示“未关联”或“成员不可用”，不导致页面报错。
- 本地数据读取失败时回退到演示数据，不覆盖无法解析的原始存储值。
- 搜索或筛选没有结果时显示筛选空状态，并提供重置入口。

## 9. 视觉与响应式要求

- 延续原 HTML 的蓝白配色、圆角卡片、字体、间距、表格、标签和按钮样式。
- 使用原有图标函数，不引入新的外部资源或构建依赖。
- 桌面端保持信息密度；窄屏下卡片改为单列或双列，表格允许横向滚动。
- 首页首屏不因新增内容显著变长，新模块放在现有核心指标与项目区域之后。

## 10. 验证标准

- 原始 HTML 未发生变化。
- 融合版可以独立加载，标题、侧边栏和默认驾驶舱可见。
- 客户、活动、业务决策三个导航入口均能打开对应页面。
- 至少验证一次客户筛选、一次活动切换和一次业务决策状态变更。
- 状态变更刷新后仍能从本地存储恢复。
- 顶部搜索能够搜索新增的客户与活动记录。
- AI 调度、项目、任务、知识库和 Agent 等原有主要页面仍能打开。
- 浏览器控制台没有与融合改动相关的错误或警告。
- 完成桌面和移动视口截图检查，确认没有明显遮挡、溢出或不可读文本。

## 11. 非目标

- 不开发考勤、请假、发薪或传统工资管理。
- 不改动线上 Next.js 项目、Supabase 数据库或生产部署。
- 不接入真实 CRM、支付、银行或人事系统。
- 不重构原单文件为 React、Vue 或多文件工程。
- 不在本轮实现真实飞书通知或外部任务下发。

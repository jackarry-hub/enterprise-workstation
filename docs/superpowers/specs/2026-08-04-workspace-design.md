# 工作中心页面设计说明

## 目标

`/workspace` 是企业员工每天进入系统后的工作入口，帮助用户在一个页面内看清今天要做什么、哪些事项临近截止、是否有审批/通知，以及日报是否已经完成。

## 视觉方向

- 延续现有企业工作站的白蓝渐变背景、半透明玻璃卡片、柔和阴影和大圆角。
- 桌面端使用全局 Sidebar/Header，内容区保持低密度、无传统表格堆叠。
- 移动端参考已提供的“工作”页面：概览聚合为一张卡片，任务采用纵向信息流，重点操作保持大触控区域。

## 信息架构

1. 页面标题与数据来源状态。
2. 今日工作概览：今日任务、待审批、截止提醒、本周完成率。
3. 我的任务：支持按全部/进行中/待完成筛选；每项显示项目、负责人、截止时间、优先级、状态和进度。
4. 今日待办：统一承载任务、审批和通知。
5. 工作日报：选择项目，填写今日完成、遇到问题、明日计划；Mock 模式本地反馈，Supabase 模式真实保存。
6. 最近动态：按时间倒序显示项目动态。

## 业务流程与角色

- 普通员工：从“我的任务”进入当天执行事项，处理跨来源待办，填写日报形成执行反馈。
- 项目负责人：通过任务完成情况和日报掌握成员执行状态，后续回到项目详情推进里程碑。
- 管理层：通过概览和最近动态快速判断执行节奏，不在工作中心直接介入复杂项目管理。
- 工作中心承接“目标 → 项目 → 任务 → 执行 → 反馈 → 复盘”中的任务、执行和反馈环节；项目名称、任务状态和项目动态保持可追溯关联。

## 数据策略

- Demo V1.0 明确使用整页 Mock，数据契约保持与 `tasks`、`project_members`、`projects`、`daily_reports`、`project_activities` 对齐。
- 后续接入 Supabase 时仍采用整页同源装配，避免将 Mock 身份混入真实业务数据。
- 审批和通知尚无业务表时，真实数据模式显示空状态；演示模式提供清晰标识的示例数据。

## 边界

- 不新增任务中心、审批中心或通知中心页面。
- 不实现任务编辑、审批处理和通知详情。
- 仅完成工作中心页面框架、核心筛选、日报提交反馈与响应式 UI。

# 企业工作站客户演示版设计

状态：已确认

设计日期：2026-08-12

目标目录：`E:\企业工作站-客户演示版`

## 1. 目标

在不修改正式项目工作区的前提下，交付一个可供客户现场操作的独立演示版本。演示版包含 10 名不同部门、岗位和职责的人员，支持在同一浏览器内切换身份，并跑通“决策下发 → 部门承接 → 员工执行 → 成果提交 → 负责人验收 → 决策人总验收 → 归档复盘”的完整闭环。

成功标准：

- 10 名人员均可从演示身份菜单进入自己的岗位首页。
- 所有身份共享同一套演示项目与流程状态，切换身份不会丢失上一人的操作。
- 页面导航、任务范围、可执行动作和通知随当前身份变化。
- 下发、执行、阻塞、协同、成果提交、退回、验收、总验收和归档均有明确状态与权限校验。
- 演示数据可一键恢复到确定的初始状态，重复演示结果一致。
- 演示模式不读取真实 Supabase 会话，不写入正式数据库，也不复制正式环境密钥。

## 2. 交付边界

演示版复用当前 Next.js 15、React 19、Tailwind、shadcn 组件、项目/任务领域动作和现有视觉体系。只新增演示身份、统一主数据、共享演示状态、重置能力和闭环验收，不重新设计页面，不建设新的生产认证或数据库后端。

演示版作为独立 Git worktree 位于 `E:\企业工作站-客户演示版`，分支为 `codex/customer-demo`。正式目录 `E:\新企业工作站` 不接受本功能修改。

## 4. 演示场景

主场景固定为“30 天完成星云智造 AI 企业工作站试点上线”。初始数据包括一个企业目标、一个试点项目、10 项跨部门任务、任务依赖、唯一执行人、唯一验收人、验收标准、协同请求和可下载的示例成果。

核心任务覆盖：试点章程、技术方案、三角色工作流、前端实现、回归测试、客户调研、试点交付、使用培训、预算审核和 RACI/权限确认。每名演示人员至少承担一个可展示职责，避免出现能切换但没有业务内容的空身份。

## 5. 身份切换

演示版用 `DemoSessionProvider` 提供当前身份，默认身份为林远。右上角用户菜单显示“切换演示身份”，列出 10 名人员的姓名、部门、岗位和身份标签。

切换行为：

1. 保存新的当前身份 ID。
2. 立即更新全局会话、导航、通知和岗位信息。
3. 跳转到该身份的 `landingPath`。
4. 不更换演示业务状态存储键，因此能继续上一身份留下的流程。

演示身份只存在于独立演示版。正式项目继续使用真实 `WorkspaceSession`，不恢复生产环境的本地身份模拟。

## 6. 共享状态与重置

演示业务状态以场景为范围，统一使用版本化键 `enterprise-workstation.customer-demo.v1`。身份选择使用独立键 `enterprise-workstation.customer-demo.actor.v1`，两者不得互相嵌套，也不得按用户分裂业务状态。

状态加载规则：

- 存储为空时加载标准种子数据。
- JSON 损坏、版本不符或关键关联缺失时自动恢复标准种子数据。
- 所有写入先通过领域动作校验，再一次性保存新状态并广播刷新事件。
- “重置演示数据”需要二次确认，成功后恢复标准种子数据、保留当前身份并返回该身份首页。

## 7. 闭环规则

主状态统一展示为待开始、执行中、待验收、已完成；阻塞和逾期作为风险标签。

- 只有任务执行人可以开始、更新进度、上报阻塞和提交验收。
- 前置依赖未完成时不能开始任务。
- 提交验收前必须存在至少一个成果文件。
- 部门负责人验收下属任务；负责人本人执行的任务由决策人验收。
- 验收人退回时必须填写意见；任务回到执行中，成果和历史记录保留。
- 验收通过时任务进度变为 100%，项目进度同步重算，并生成知识条目。
- 有未完成任务或未关闭协同请求时，不能完成总验收。
- 总验收后可归档；归档后核心流程只读，并保留操作事件、成果和复盘资料。

## 8. 页面调整

复用现有页面和组件，只做与演示闭环直接相关的调整：

- 顶部用户菜单增加演示身份切换和重置入口。
- 人员目录显示统一的 10 人资料、部门、岗位、直属负责人和账号角色。
- 项目、任务、工作台、通知和搜索统一解析演示人员目录。
- 决策调度台下发后，任务在项目中心、任务中心和各岗位工作台同步出现。
- 演示成果使用项目内置真实文件，可下载、提交并参与验收校验。

## 9. 错误处理

- 未知身份 ID：恢复默认决策人，不渲染空白工作台。
- 未知人员、部门、任务或验收人引用：拒绝加载损坏状态并恢复种子数据。
- 越权操作：不修改状态，显示当前身份不能执行该操作。
- 非法状态跳转：保持原状态并给出允许的下一步。
- 重复点击下发、提交或验收：领域动作保持幂等，不生成重复任务和事件。
- 浏览器存储不可用：本次会话使用内存状态并显示刷新后会重置的提示。

## 10. 测试与现场验收

自动化至少覆盖：

- 10 人目录、稳定 ID、部门、岗位、系统身份和直属关系完整。
- 人员目录、项目成员和流程参与人引用同一主数据。
- 身份切换后岗位首页、导航和权限正确，业务状态保持共享。
- 员工完整执行“开始 → 上传成果 → 提交验收”。
- 负责人完整执行“退回 → 员工重提 → 通过”。
- 负责人自己的任务由决策人验收。
- 前置依赖、成果文件、验收意见和总验收前置条件生效。
- 重置后恢复种子数据，损坏数据自动恢复。
- 10 个身份无控制台异常、无白屏、无越权入口。
- 全量单元测试、类型检查、代码规范检查、生产构建和浏览器闭环验收通过。

现场固定演示顺序：林远下发 → 陈晨执行并提交 → 张伟退回 → 陈晨补充后重提 → 张伟通过 → 周倩和李琪处理协同 → 郭敏提交测试报告 → 林远完成总验收并归档 → 重置场景。
